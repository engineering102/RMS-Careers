# Orientation: how this programme works and how to learn

## What the next 26 weeks look like

The programme is built in six phases. Each phase ends with something you can show an interviewer.

| Phase | Weeks | You will be able to… | Proof you build |
|---|---|---|---|
| 1 · Foundations & Engineering Tools | 1–4 | Write clean Python, use the terminal and Git daily | Python OOP command-line app (MP1) |
| 2 · Databases & SQL | 5–8 | Design a schema, write analytical SQL, use MongoDB | Campus placement database (MP2) |
| 3 · Full Stack Web | 9–15 | Build and deploy a React + Node.js app | Deployed full stack app (MP3) |
| 4 · Data & AI | 16–19 | Wrangle data, build dashboards and ML models, call LLM APIs | Data / AI application (MP4) |
| 5 · SAP S/4HANA | 20–22 | Explain core ERP processes in FI/CO, MM and SD | SAP end-to-end process document (MP5) |
| 6 · Capstone & Placement | 23–26 | Plan, build and demo a team product; interview with confidence | Capstone + Demo Day |

Running alongside every week:

- **DSA stream**: one problem-solving pattern a week, practised on the Pattern Path sheet.
- **Career & portfolio**: a small task each week (profiles, résumé, LinkedIn, mock interviews).

## The four career tracks

You do not have to choose on Day 1, but you should start forming a target.

- **Software Development Engineer (SDE)**: DSA, a strong language, system fundamentals, projects with clean code.
- **Web / Full Stack Developer**: HTML/CSS/JS, React, Node.js, databases, deployment.
- **Data / AI**: Python, SQL, Pandas, visualisation, machine learning, LLM applications.
- **SAP / ERP consultant**: business processes, SAP S/4HANA modules, documentation and communication.

This week you record a **primary** and a **backup** target role. You can change them later; having them makes every
week's choices easier.

## Your weekly rhythm

Every week follows the same pattern, so you always know what to do next.

1. **Before class**: skim the session notes for the week (10 minutes each).
2. **Sessions S1–S4**: concept, then a hands-on lab. Code along; do not just watch.
3. **DSA stream**: solve the week's Pattern Path problems. Aim for one problem a day rather than all on Sunday.
4. **Practice quiz**: untimed, unlimited retakes. Use it to find gaps.
5. **Weekly test**: timed, one attempt. It shows you and your tutor where you stand.
6. **Weekly build**: a small project pushed to GitHub. Every week ends with something committed.

## How to learn programming (what actually works)

**Type the code yourself.** Copy-pasting skips the part where your brain learns the syntax. Retype examples, then
change them and predict what will happen before you run them.

**Predict, then run.** Before pressing Run, say what you expect the output to be. When you are wrong, that is the
moment you learn something. Keep a short "surprises" list in your notes.

**Trace on paper.** For loops and recursion, draw a small table of variable values line by line. Tutors consistently
see that students who hand-trace code become strong at DSA.

**Get stuck on purpose, for a limited time.** Struggle for 20–30 minutes before asking for help. Then ask a precise
question: what you tried, what you expected, what happened, and the exact error message.

**Spaced repetition beats cramming.** Revisit a topic after 1 day, 3 days and 7 days. The Pattern Path deliberately
brings old patterns back for this reason.

**Teach it back.** If you can explain a concept to a friend in two minutes without notes, you understand it.

## Rules of the road

- **Attendance and labs count.** Lab work is where skills form; missing labs is the fastest way to fall behind.
- **Academic honesty.** Discussing ideas is encouraged. Submitting someone else's code as yours is not. AI tools are
  allowed for explanations, but you must be able to explain every line you submit.
- **Commit every week.** Your GitHub history becomes part of your portfolio. Small, regular commits look far better
  than one large upload at the end.

## The baseline diagnostic

In S1 you take a short diagnostic test. **It is not graded.** It only helps your tutor form mixed-ability peer groups,
so each group has someone confident to lean on. Answer honestly; guessing makes the groups worse for you.
